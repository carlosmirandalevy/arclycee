## Descripción General

Este documento recoge todas las ideas, preferencias e instrucciones básicas e iniciales para el videojuego que la clase de Robótica del Liceo Francés de Santo Domingo \- 2026 está trabajando para una competencia.

### Consideraciones

Queremos que el juego sea súper divertido, súper original, que tenga un lore expansivo, que tenga una historia central y varios side quests.

Es muy importante el game mechanics: los controles y los movimientos de los personajes deben sentirse suaves y naturales y responder adecuadamente a los mandos.

Debe funcionar bien en desktop y en móvil (con mandos simulados en pantalla).

Podemos hacer referencia a la Cultura Pop.

Podemos desarrollar todo en dos versiones: CupHead cartoon style y Pixel Art. Iniciemos con Pixel Art si es difícil mantener ambos.

Queremos que el juego tenga easter eggs y secretos.

# Decisiones Adicionales de Diseño

## Inicio

* Iniciamos con el Mundo Taíno y las Cuevas del Pomier.

## Plataforma

* 2D RPG (top-down with platformer areas) using vanilla HTML5 Canvas and JavaScript as the primary stack with some functionality from Kaplay.js

### Framework

* Use Kaplay.js ONLY for tilemap loading/rendering (Tiled editor integration), touch input abstraction (virtual d-pad for mobile), and sprite sheet animation management.  
* Everything else — game logic, player mechanics, physics, NPC AI, dialogue system, quest engine, inventory, combat, realm transitions, weather, the Cemí power progression, multiple endings— must be vanilla JS in clearly organized, well-commented modules.

### Code, Architecture and Documentation

* We are 9 \- 14 year old students of robotics/research class.  
* We need to READ, EXPLORE, and SUGGEST modifications to the code.  
* The \#1 architectural priority is code readability and inspectability:  
  * clean file organization, extensive Spanish comments explaining the logic, descriptive variable/function names in Spanish, and no minified or opaque dependencies.  
* Each source file should be understandable by a 13-year-old exploring via browser DevTools or VS Code.  
  * When someone asks 'how does the hurricane work?' we should be able to open clima/huracan.js and walk through it line by line.  
* File and folder structure must mirror the game design document's concepts — organized by game world, mechanic, and character rather than by technical pattern.  
  * For example: personajes/pepito.js, mundos/taino/cuevas.js, mecanicas/inventario.js, clima/huracan.js, misiones/secundarias/.  
  * Anyone should be able to navigate the codebase using the same vocabulary and structure as their game concept document.  
* Every function should do ONE clear thing with a Spanish comment explaining WHY, not just WHAT.  
  * Prefer explicit readable code over clever abstractions: if (jugador.tieneLinterna) is better than a generic equipment bitmask pattern, even if less elegant.

# Sistema de Mapas: Arquitectura, Herramientas y Recursos

## Dos Sistemas de Mapas Separados

El juego tiene dos sistemas de mapas fundamentalmente diferentes que deben mantenerse arquitectónicamente separados:

### Mapa del Juego (Kaplay tiles)

El mundo jugable donde Pepito camina, pelea y explora. Se renderiza como game tiles del editor Tiled. Es parte del motor del juego — Kaplay maneja el renderizado, la colisión y la cámara. Piensen en Stardew Valley o Undertale: el "mapa" es simplemente el mundo del juego renderizado en tiles.

### Mapa de Referencia (Leaflet.js)

Un overlay interactivo que se abre como panel de UI (como el inventario o un menú de pausa). Cuando el jugador abre "el mapa" desde su inventario, Leaflet renderiza dentro de un panel con capas artísticas personalizadas y capas de tiles interactivos.

La conexión entre ambos es lógica del juego, no renderizado: cuando el jugador hace clic en una ubicación en el mapa de referencia de Leaflet, la lógica vanilla JS del juego activa una transición de realm en el mundo del juego Kaplay.

## Por qué Leaflet y No OpenLayers

Leaflet es deliberadamente liviano y simple (\~42KB), con un API intuitivo que cualquiera de nosotros y otros estudiantes pueden leer y entender. OpenLayers es un sistema GIS profesional completo (\~400KB+) con abstracciones más profundas y complejidad innecesaria para nuestro caso de uso. No trabajan juntos — son soluciones competidoras. Leaflet es la opción clara para nuestra prioridad de legibilidad.

## Tile Sources: URLs Exactos para Cada Capa Histórica

### Autenticación y Costos

* Para desarrollo local en localhost o 127.0.0.1, no se necesitan API keys ni configuración de dominio.

* El tier gratuito incluye 2,500 créditos por mes (1 crédito por tile raster request) — suficiente para desarrollo y demos.  
* Para producción en Firebase, se necesita whitelist del dominio o agregar `?api_key=YOUR-API-KEY` al URL.

## Plugins de Animación para Leaflet

### Leaflet.Polyline.SnakeAnim — Animación de Rutas

Anima las polilíneas para que se dibujen gradualmente, como trazando una ruta de explorador en un pergamino. Perfecto para dibujar la ruta de Pepito a través de la isla.

* **GitHub:** [https://github.com/IvanSanchez/Leaflet.Polyline.SnakeAnim](https://github.com/IvanSanchez/Leaflet.Polyline.SnakeAnim)  
* **npm:** `npm i leaflet.polyline.snakeanim`  
* **Requiere:** Leaflet 1.1+  
* **Eventos:** Dispara `snakestart`, `snake` y `snakeend` — podemos activar diálogos o cutscenes cuando la animación llega a sitios específicos.

```
// Dibujar la ruta de Pepito desde la Isabela hasta Santo Domingo
var rutaPepito = L.polyline(coordenadasRuta, {
  snakingSpeed: 200, // velocidad en píxeles por segundo
  color: '#8B4513'   // marrón — como tinta en pergamino
})
rutaPepito.addTo(mapaReferencia).snakeIn()
```

### leaflet.motion — Toolkit Completo de Animación

Permite animar polilíneas y polígonos con marcadores que se mueven a lo largo de rutas. Soporta duración y velocidad, con controles de play/pause/stop. Perfecto para la canoa de Pepito moviéndose entre naufragios o galeones coloniales navegando.

* **GitHub:** [https://github.com/Igor-Vladyka/leaflet.motion](https://github.com/Igor-Vladyka/leaflet.motion)  
* **Métodos:** `motionStart()`, `motionStop()`, `motionPause()`, `motionResume()`, `motionToggle()`  
* **Soporta:** Iconos personalizados como sprites de Pepito, canoas, galeones.

### Leaflet.AnimatedMarker — Movimiento Simple de Marcadores

Anima un marcador a lo largo de una polilínea usando CSS3, moviéndose punto a punto a una velocidad específica. Más simple que leaflet.motion, ideal para la chica mensajera en patines o rutas de patrulla de NPCs.

* **GitHub:** [https://github.com/openplans/Leaflet.AnimatedMarker](https://github.com/openplans/Leaflet.AnimatedMarker)  
* **Usa:** CSS3 animations, rate en metros por milisegundo.

### leaflet-icon-pulse — Marcadores Pulsantes

Crea iconos pulsantes con color, tamaño y ritmo configurables. Perfecto para resaltar yacimientos arqueológicos sin descubrir, misiones activas, artefactos en peligro o la posición actual de Pepito.

* **GitHub:** [https://github.com/mapshakers/leaflet-icon-pulse](https://github.com/mapshakers/leaflet-icon-pulse)  
* **npm:** `npm install @ansur/leaflet-pulse-icon`

```
// Marcar un yacimiento arqueológico por descubrir — pulsa en dorado
var iconoPulsante = L.icon.pulse({
  iconSize: [20, 20],
  color: 'gold',
  fillColor: 'orange',
  heartbeat: 1.5
})
var yacimiento = L.marker([18.4861, -69.9312], {
  icon: iconoPulsante
}).addTo(mapaReferencia)
```

### Leaflet.MarkerPlayer — Animación Avanzada con Control de Progreso

Anima marcadores a lo largo de polilíneas con control de progreso (get/set), pausa, estaciones (paradas) y eventos. Perfecto para secuencias de tour guiado donde Pepito visita sitios en orden con pausas para información.

* **GitHub:** [https://github.com/0n3byt3/Leaflet.MarkerPlayer](https://github.com/0n3byt3/Leaflet.MarkerPlayer)  
* **Features:** `setProgress()`, `getProgress()`, `addStation()`, soporte para loops.

## Creación de Tiles Personalizados

Tres métodos para crear nuestros propios tiles artísticos:

### Método A: Slicear Imágenes Artísticas con GDAL2Tiles

El flujo es: crear una imagen artística grande → cortarla en tiles 256x256 → organizarlos en estructura `{z}/{x}/{y}`.

#### Paso 1: Crear el Arte

Usar MidJourney o Nano Banana Pro para generar mapas artísticos de alta resolución de la República Dominicana:

* **Capa Taína:** Mapa que parezca pintura en pared de cueva — tonos terrosos, petroglifos como decoración, la isla en ocre y carbón.  
* **Capa Colonial:** Estilo cartografía española del siglo XVI — textura de pergamino, rosa de los vientos, monstruos marinos en el Caribe, caligrafía ornamental.  
* **Capa Submarina:** Acuarela azul-verde profundo con naufragios marcados como barcos dibujados a mano.

#### Paso 2: Cortar en Tiles

**Para imágenes artísticas sin georreferencia (mapa ficticio/estilizado):**

gdal2tiles.py \-p raster \-z 0-6 \-w leaflet \-r average mapa\_taino\_artistico.png tiles/taino/

El flag `-p raster` maneja imágenes sin coordenadas geográficas reales.

**Para mapas georreferenciados (alineados con República Dominicana real):**

Primero georreferenciar con QGIS Georeferencer (actividad excelente para la clase — los estudiantes hacen clic en puntos reconocibles del mapa artístico y entran coordenadas GPS reales). Luego:

gdal2tiles.py \-p mercator \-z 5-14 \-w leaflet mapa\_colonial\_georef.tif tiles/colonial/

**Alternativa por línea de comandos con gdal\_translate:**

Bounding box de República Dominicana: \~17.5°N a 19.9°N, \-72.0°W a \-68.3°W:

```
gdal_translate -of VRT -a_srs EPSG:4326 \
  -gcp 0 0 -72.0 19.9 \
  -gcp WIDTH 0 -68.3 19.9 \
  -gcp WIDTH HEIGHT -68.3 17.5 \
  -gcp 0 HEIGHT -72.0 17.5 \
  mapa_artistico.png mapa_georef.vrt
gdalwarp -of VRT -t_srs EPSG:3857 mapa_georef.vrt mapa_mercator.vrt
gdal2tiles.py -p mercator -z 5-14 -w leaflet mapa_mercator.vrt tiles/custom/
```

#### Paso 3: Hospedar y Servir

Copiar la estructura de folders de tiles a GitHub Pages o Firebase hosting. En Leaflet apuntamos a ellos:

```
const capaArtistica = L.tileLayer(
  'https://your-firebase-url.com/tiles/taino/{z}/{x}/{y}.png', {
    maxZoom: 14,
    attribution: 'Mapa artístico — Clase de Robótica LFSD 2026'
  }
)
```

### Método B: Canvas Tile Layer (Procedural, Sin Pre-Generación)

Leaflet permite crear tiles dinámicamente usando Canvas, extendiendo `L.GridLayer` con `createTile()`. Poderoso para efectos procedurales como niebla de guerra que se aclara cuando Pepito descubre sitios, o una capa de contaminación que se renderiza dinámicamente según el estado del juego.

```
// Capa de niebla de guerra — se aclara cuando Pepito descubre sitios
L.GridLayer.NieblaDeGuerra = L.GridLayer.extend({
  createTile: function(coords) {
    var tile = document.createElement('canvas')
    var tileSize = this.getTileSize()
    tile.width = tileSize.x
    tile.height = tileSize.y
    var ctx = tile.getContext('2d')
    
    // Dibujar niebla oscura por defecto
    ctx.fillStyle = 'rgba(0, 0, 0, 0.7)'
    ctx.fillRect(0, 0, tileSize.x, tileSize.y)
    
    // Borrar las áreas que Pepito ya descubrió
    // (basado en el estado del juego)
    
    return tile
  }
})
```

### Método C: MapTiler (Herramienta GUI)

MapTiler ([https://www.maptiler.com/](https://www.maptiler.com/)) provee una interfaz visual para crear y hospedar tiles personalizados que trabajan directamente con Leaflet. Es esencialmente un GUI wrapper alrededor del proceso de tiling con GDAL. Más fácil para que los estudiantes entiendan, pero menos hands-on.

### Recomendación

Usar una combinación de Método A y Método B:

* **Método A** para las capas base artísticas históricas — generar mapas hermosos con MidJourney, georreferenciarlos en QGIS (gran actividad de clase), cortarlos con GDAL2Tiles, hospedar en Firebase.  
* **Método B** para overlays dinámicos del estado del juego — niebla de guerra, zonas de contaminación, áreas descubiertas/sin descubrir.  
* **Tiles de Stadia Maps** como fallbacks y para la capa moderna — son hermosos, gratis para uso académico y cubren toda la República Dominicana a alto zoom.

## REFERENCE MAP SYSTEM (Kaplay and Leaflet.js)

The game has two distinct map systems that must remain architecturally separate:

\*\*Game Map (Kaplay tiles):\*\* The playable world where Pepito walks, rendered as game tiles from Tiled editor. This is part of the game engine — Kaplay handles rendering, collision, and camera.

\*\*Reference Map (Leaflet.js):\*\* An interactive overlay map that opens as a UI panel (like inventory). Uses Leaflet with custom artistic tile layers. Supports layer toggling between historical periods, animated markers for archaeological sites and shipwrecks, and click-to-travel functionality that triggers realm transitions in the game world.

Do NOT use OpenLayers. Leaflet is the choice for readability and simplicity.

Tile sources with exact URLs:

\- Watercolor (historical): \`https://tiles.stadiamaps.com/tiles/stamen\_watercolor/{z}/{x}/{y}{r}.png\` (maxZoom: 16\)

\- Terrain: \`https://tiles.stadiamaps.com/tiles/stamen\_terrain/{z}/{x}/{y}{r}.png\`

\- Toner (B\&W): \`https://tiles.stadiamaps.com/tiles/stamen\_toner/{z}/{x}/{y}{r}.png\`

\- Toner Lite: \`https://tiles.stadiamaps.com/tiles/stamen\_toner\_lite/{z}/{x}/{y}{r}.png\`

\- Modern OSM: \`https://tile.openstreetmap.org/{z}/{x}/{y}.png\`

\- Custom artistic: \`tiles/custom/{layer}/{z}/{x}/{y}.png\` (locally hosted)

Authentication: Free tier (academic use), domain auth or API key for production Firebase deployment. No auth needed for localhost.

Animation plugins to include:
