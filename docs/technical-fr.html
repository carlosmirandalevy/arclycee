Principes de Conception

  • Lisibilité d'abord : code commenté en espagnol, lisible par des élèves de 13 ans
  • Pas de dépendances lourdes : uniquement LeafletJS pour les cartes, tout le reste en vanilla
  • Son procédural : effets générés avec Web Audio API, sans fichiers
  • Sprites programmatiques : tous les personnages et bâtiments dessinés avec Canvas 2D
  • 3 langues : espagnol, français et anglais — toute chaîne visible est traduite

Architecture du Moteur

Le code est organisé en modules ES6 :

ModuleFichierResponsabilité
Boucle de Jeujs/motor/juego.jsBoucle principale, gestion des scènes, inventaire, combat, batú, toasts, sauvegarde
Entréejs/motor/entrada.jsEntrée unifiée (clavier + tactile) via estaPresionada(action)

Rendujs/motor/renderizado.jsWrapper Canvas 2D
Sonjs/motor/sonido-procedural.jsEffets avec Web Audio API
Sauvegardejs/motor/guardado.jsPersistance dans localStorage

Cycle de Vie des Scènes

Chaque scène implémente :

  • iniciar(juego) — configuration initiale à l'entrée
  • actualizar(dt, entrada, jugador, companeros) — logique par frame
  • dibujar(renderizador, ancho, alto, textos, jugador, companeros) — rendu

Changement de scène avec juego.cambiarEscena('nom'). Une seule scène active à la fois.

Système de Sauvegarde

Sauvegarde automatique au retour sur la carte. Données sérialisées :

  • Scène actuelle, genre du personnage, langue
  • Vie du joueur
  • Progression (nœuds complétés et débloqués)
  • Inventaire complet (objets avec nom, description, type)
  • Compagnons (type + état actif/inactif)
